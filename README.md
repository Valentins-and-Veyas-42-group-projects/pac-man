# Pac-Man

## Description

A recreation of the classic 1980 arcade game Pac-Man, built in Python
with pygame for the 42 curriculum's "Ghosts! More ghosts!" subject.
The player eats pacgums while avoiding four autonomously-moving
ghosts, with super-pacgums making the ghosts temporarily edible.
Levels are generated by an external `A-Maze-ing` package assigned to
this group, and the top 10 scores are kept in a persistent, SQLite-
backed highscore table.

This scaffold is currently structure-only: data types, module
boundaries, the CLI entry point, and error-handling infrastructure
are in place, but the actual game loop, rendering, maze adaptation,
and highscore persistence are left as stubs to implement.

## Instructions

### Requirements

- Python 3.10 or later
- [`uv`](https://docs.astral.sh/uv/) (recommended)

### Install

```bash
make install
```

### Run

```bash
make run
```

Or manually:

```bash
python3 pac-man.py config.json
```

The program takes exactly one argument: a path to a JSON config file
(see [`config.example.json`](config.example.json)). Lines starting
with `#` are treated as comments.

### Other Makefile targets

| Target | Description |
| --- | --- |
| `make debug` | Run under `pdb` |
| `make clean` | Remove caches and build artifacts |
| `make lint` | Run flake8 + mypy |
| `make lint-strict` | Run flake8 + mypy `--strict` |
| `make test` | Run pytest |

## Configuration

The config file is JSON with `#`-style comments. Recognized keys, all
with safe defaults if missing or invalid (see
[`pacman/config.py`](pacman/config.py)):

| Key | Default | Description |
| --- | --- | --- |
| `highscore_filename` | `highscores.json` | Highscore storage location |
| `levels` | one 21x21 level | Array of `{width, height}` per level |
| `lives` | `3` | Starting player lives |
| `pacgum` | `42` | (reserved, see `pacman/config.py`) |
| `points_per_pacgum` | `10` | Score per pacgum eaten |
| `points_per_super_pacgum` | `50` | Score per super-pacgum eaten |
| `points_per_ghost` | `200` | Score per edible ghost eaten |
| `seed` | `42` | Seed for level 1's maze |
| `level_max_time` | `90` | Seconds allowed per level |

Unknown keys are ignored; missing or invalid values are clamped to
defaults with a logged warning, never a Python traceback.

## Highscore

Highscores are persisted in a local SQLite database (see
[`pacman/highscores/store.py`](pacman/highscores/store.py)), keeping
the top 10 `(name, score)` rows. Names are max 10 characters,
alphanumeric and spaces only; scores are non-negative integers,
enforced with a `CHECK` constraint in the schema. Highscores are
loaded at game start and saved at game end (win or lose), and shown
in the main menu.

SQLite was chosen over a flat JSON file so score validation (the
non-negative constraint) is enforced by the storage layer itself
rather than by application code alone.

## Maze Generation

Per the subject, this project does not implement its own maze
generator. At project start we're assigned another group's
`A-Maze-ing` package and must adapt our loader to its interface (see
[`pacman/maze_loader.py`](pacman/maze_loader.py)), calling it with
`PERFECT = False` so the resulting maze has multiple valid paths
rather than exactly one. The stub currently assumes the shared
`mazegen.MazeGenerator` shape (4-bit wall-encoded grid cells) used
across this org's own A-Maze-ing implementations; the import will be
swapped for whichever package is actually assigned.

## Implementation

- `pacman/errors.py`, `pacman/cli_fw.py` -- a `Result`/`Ok`/`Err`
  error-handling pattern and a reflection-based CLI argument parser,
  ported from
  [never-hire-me-for-python](https://github.com/0xveya/never-hire-me-for-python)
  so error handling stays consistent across this group's projects.
  Errors are always returned as values and printed as clean
  diagnostics, never as raw tracebacks.
- `pacman/config.py` -- config loading/validation.
- `pacman/models.py` -- shared data types (`Position`, `Direction`,
  `Player`, `Ghost`, `Screen`, `HighscoreEntry`).
- `pacman/maze_loader.py` -- adapter over the assigned A-Maze-ing
  package.
- `pacman/highscores/` -- SQLite-backed persistent highscore table.
- `pacman/game/` -- board, player, ghosts, cheat flags, and the
  top-level game state machine.
- `pacman/visualizer/` -- pygame-based rendering (currently an empty
  stub, one method per UI screen).
- `pac-man.py` -- the root entry point required by the subject's
  exact invocation.

## General Software Architecture

```text
pac-man.py                  entry point (python3 pac-man.py config.json)
pacman/
├── main.py                 wires CLI args -> config -> game loop
├── cli_fw.py, errors.py    reusable CLI + Result/Err infrastructure
├── config.py                Config dataclass + loader
├── models.py                 shared data types
├── maze_loader.py            A-Maze-ing adapter -> Maze
├── highscores/store.py       SQLite top-10 highscore table
├── game/
│   ├── board.py               Maze + remaining pacgums
│   ├── player.py               player movement
│   ├── ghosts.py                ghost chase/flee/respawn behavior
│   ├── cheat.py                  cheat mode flags
│   └── state.py                   GameState machine tying it together
└── visualizer/renderer.py    pygame rendering, one method per screen
```

`GameState` (in `pacman/game/state.py`) owns the current `Screen`,
`Board`, `Player`, and list of `Ghost`s. The main loop (once
implemented in `pacman/main.py`) will alternate between polling input
via `Renderer.handle_input()`, advancing `GameState` via
`game.state.update()`, and drawing the current frame via
`Renderer.render()`.
